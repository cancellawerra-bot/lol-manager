# LOL Manager 핸드오프

다른 에이전트·개발자가 이어서 작업할 때 먼저 읽습니다. 비밀·토큰·자격 증명은 이 문서와 저장소에 넣지 않습니다. 시간은 아시아/서울(UTC+9)입니다.

- 라이브: https://cancellawerra-bot.github.io/lol-manager/
- 저장소: https://github.com/cancellawerra-bot/lol-manager (브랜치 `main`, 배포는 `gh-pages`)
- 이 문서 작성·갱신 시점: 2026-11-18 (서울). 로컬 코드 헤드는 v2.4.4. 측정 목표는 v2.4.4에서 달성했습니다. 배포 상태는 「12. 알려진 문제와 다음 단계」를 보세요.

---

## 1. 프로젝트 목표

무료 비상업 브라우저 게임입니다. **실제 LCK 시즌 카드(2012–2026)** 와 2026 시즌 기록으로 구단을 운영합니다. v2부터 기본 모드는 **프랜차이즈 스토리**: 2018 2부(챌린저스) 창단 → 2018–2020 승강전으로 LCK 승격 → 2021 프랜차이즈 자리 유지 → **2027 월즈 우승으로 클리어**.

운영: 홍승표 (신구대학교 e스포츠과) · 교육용 팬 프로젝트. 게임 이름은 반드시 **LOL Manager**입니다.

한 시즌만 운영하는 2026 실제 로스터 모드와 판타지 드래프트는 보조로 남아 있습니다. 원작식 2016 히스토리 모드는 「준비 중」입니다.

## 2. 오너 규칙 (깨면 안 되는 것)

설계·밸런스·UI를 바꿀 때 아래를 유지합니다. 의심스러우면 코드를 고치기 전에 오너에게 확인합니다.

1. **비상업.** Riot Legal Jibber Jabber 고지를 타이틀·푸터·도움말에 유지합니다. Riot·LCK·구단과 무관함을 밝힙니다.
2. **이름는 LOL Manager.** 다른 타이틀로 바꾸지 않습니다.
3. **시각 자산.** Riot Data Dragon 챔피언 아이콘만 사용합니다. **팀 로고·선수 사진은 쓰지 않습니다.** 구단은 약칭·텍스트·단색만.
4. **실데이터만.** 선수 능력치·연봉 카드 수치·랭크 상성을 지어내지 않습니다. 계산은 공식과 소스 기록에서만 나옵니다.
5. **없는 기록은 0이 아닙니다.** 결측 지표는 비우고, 화면에는 **「기록 없음」** (또는 표본 부족)으로 표시합니다. 빈 값을 0으로 채워 평균을 깎지 않습니다.
6. **돈은 게임용 가상 금액**입니다. UI에 「게임용 가상 금액」 / 실제 계약과 무관함을 남깁니다. LCK 카드 연봉 공식은 판타지 가격입니다.
7. **2부 연봉 규모.** 전형 구간은 2천만~5천만 원(0.2–0.5억), 이름 있던 선수는 가산되어 더 높고 상한은 약 2억(`CK_SALARY_MAX`). LCK 소속 연봉은 카드 공식 그대로입니다.
8. **시즌 카드 규칙**
   - Y시즌에는 Y년 카드를 씁니다. 없으면 가장 가까운 과거 카드 + 「추정」표시.
   - 미래 연도 카드는 시장에 나오지 않습니다. 데뷔 이전 연도에도 나오지 않습니다.
   - `DECAY_PCT = 15`, 바닥 종합 5. **2026 공식 카드는 2027에도 감쇠 없이 그대로** 씁니다(2027 본선 기록이 없음).
9. **경기 결과를 조작·강제하지 않습니다.** 클리어율을 맞추려고 시뮬 승패를 하드코딩하지 않습니다. QA 훅(`?qa=1`)도 자동 진행·입찰만 하며 승패를 바꾸지 않습니다.
10. **스토리 클리어**는 2027 월즈 우승뿐입니다. 강등되어도 게임 오버가 아닙니다. 파산(`CASH_BANKRUPT = -5`억 이하) 또는 2027 미우승은 실패 엔딩입니다.

상세 설계는 `docs/STORY_MODE.md`. 시즌 카드·연봉 조사는 `docs/research/SEASON_CARDS.md`.

## 4. 데이터 파이프라인

지어낸 숫자를 넣지 않습니다. 소스 파일은 읽기만 하고, LeagueLab DB를 수정·삭제하지 않습니다.

### 시즌 카드 (`tools/build_cards.py`)

- 입력: `/workspace/lolmanager-research/seasons/derived/all_player_seasons.csv`
- 출력: `public/data/cards.json` (1,011장, 10경기 이상)
- 원천(조사 단계): Oracle's Elixir 연간 CSV, ChainCC, Leaguepedia Cargo(2012–2014 보완). 상세는 `docs/research/SEASON_CARDS.md`.
- 종합(퍼센타일)은 **그해·그 포지션 안**에서 정규화합니다. 시대 간 분당 딜을 직접 비교하지 않습니다.
- **LCK 연봉 공식(카드에 적힌 값, 게임용 가상 금액):**  
  `round(3 + 47 × (퍼센타일/100)^2.5)`억.
- **2부 연봉(스토리, `storySalary` / `ckSalary`):** 퍼센타일 75 이하 0.20–0.50억, 그 위는 최대 1.00억 기본 + 이름 가산(피크 70/80/90, 3–4시즌). 최종 클램프 0.2–2억.

### 2026 코어·밴픽 (`tools/build_data.py`)

```
python3 tools/build_data.py [랭크 matches.jsonl 경로]
```

입력(읽기 전용):

- LeagueLab DB `/workspace/leaguelab-collector/data/live.sqlite`
- 확정 지표 `/workspace/leaguelab-metrics/outputs/lck2026-*.locked.json`
- 랭크 경기 기본 경로 `/workspace/lolmanager-research/banpick-source/data/matches.jsonl` (lol-banpick-lab `source` 브랜치 사본)
- Data Dragon 16.22.1 `tools/ddragon_{ko,en}.json`, `tools/champs_meta.json`

출력: `public/data/core.json`, `champs.json`, `ranked.json`. 30판 미만 랭크 상성/시너지는 저장하지 않습니다. 계산 방법은 게임 안 「데이터 출처·방법」 페이지와 같습니다.

## 5. 빌드 · 테스트 · 배포 · 측정

```bash
# 개발 (포트 5190)
npm run dev

# 타입체크 + 프로덕션 빌드
npm run build

# 미리보기 (스크립트 기본 포트 5191). QA는 종종 5192를 씁니다.
# 같은 포트에 vite preview --strictPort가 이미 있으면 두 개를 띄우지 말고, 기존 프로세스를 종료한 뒤 새 dist로 다시 띄우세요.
npx vite preview --port 5192 --host 127.0.0.1 --strictPort

# 단위 테스트
npx tsx tools/test/story.test.ts
npx tsx tools/test/season.test.ts

# 클리어·파산율 (난이도, 시작 시드, 개수). stdout이 리다이렉트되면 버퍼링되어 SUMMARY가 끝날 때까지 안 보일 수 있습니다.
npx tsx tools/test/clear_rate.ts easy 1 40
npx tsx tools/test/clear_rate.ts normal 200 40
npx tsx tools/test/clear_rate.ts hard 300 40

# QA (저장소 밖 스크립트, Playwright). 콘솔 에러 0, 뷰포트 1280×800 / 390×844.
# BASE_URL="http://127.0.0.1:5192/?qa=1" node /workspace/qa/play_v233.mjs
# 클리어 샷은 clear_rate로 확인된 시드가 안전합니다. v2.3.3 보통 시드 232가 브라우저에서도 클리어됐습니다.

# 배포: 먼저 main을 origin에 푸시하고, 그다음 배포 스크립트 (gh-pages만 force-push).
git push origin main
bash tools/deploy.sh
# 출력 예: deployed main@<short> → <gh-pages short>
# 라이브 index.html의 번들 해시(assets/index-….js)가 방금 빌드와 같은지 확인하세요. Pages는 1–2분 지연될 수 있습니다.
```

`tools/deploy.sh`는 `main`을 푸시하지 않습니다. 라이브만 올리면 저장소 `main`이 뒤처집니다. 오너가 배포를 요청하면 보통 `main` 푸시 + `deploy.sh` + 라이브 재검증을 함께 합니다.

비교용 시드 구간(오너 요청: 표본을 늘리지 말 것, 2026-11-18 기준):

- 쉬움 1–40, 보통 200–239, 어려움 300–339. 각 40시드.
- 목표: 쉬움 클리어 > 보통(약 5–20%) > 어려움, 파산은 거의 0.

`clear_rate.ts`는 `STORY_BUDGETS[difficulty]`로 `bestRoster(2018)`을 짠 뒤 `stepYear({ acceptBuyIn: true, signStars: true, reserveCash: 2020 이하이면 FRANCHISE_BUYIN })`으로 한 해를 진행합니다.

### 헤드룸이 약정 연봉을 무시함

자동 감독은 입찰 여유를 `잔고 − (매수 유보금)` 정도로 봤고, **이번 정산에서 나갈 미선납 연봉(`upcomingSalaryDue`)을 빼지 않았습니다.**

파산 23시드, 2020 스토브 입찰 직전:

- 잔고 중앙값 **74.28억**
- 곧 나갈 미선납 연봉 중앙값 **111.25억**
- `잔고 − 약정연봉` 중앙값 **−36.22억**
- **23/23이 음수 헤드룸**인데도 입찰 여유처럼 보임

2018–2020 FA 지출 중앙값은 파산 110.91 / 생존 101.33으로 총액 차이는 크지 않습니다. 문제는 “얼마를 썼나”보다 **정산 때 1년치가 한꺼번에 나가는 계약 구조**와, 그 약정을 무시한 입찰입니다. 선납 계약은 이미 빠져 있고, 미선납은 `finishStove`에서 일괄 차감됩니다.

### 강제 매각이 50%만 회수함

`forceSalesToCover` 회수금은 `연봉 × max(잔여연수, 1) × 0.5`입니다. 잔고가 0 아래로 떨어지면 벤치·고연봉부터 팝니다.

2020에 잔여 1년 계약이 많으면, 연봉 100을 정산해야 하는데 매각은 50만 돌아옵니다. 파산 23/23 모두 2020에 강제 매각 뉴스가 있습니다. 예: 시드 3은 2018에 2년 Chovy(66.7억 회수)를 팔아 한 해를 넘겼다가, 2020에 Keria·Chovy 등을 팔고도 잔고 **−8.34억**으로 끝났습니다. 보통 난이도의 일부 초과 지출 시드는 2년 잔여 스타를 거의 연봉만큼 회수해 0 또는 −4.47(임계 −5 위)로 살아남았습니다.

### 결론과 당시 권고 (이후 v2.3에 반영)

원인 순위: (1) 약정 연봉 미유보 (2) 프랜차이즈 전 캡 115가 배분 25억대 수입과 불일치 (3) 2018 조기 승격이 그 경로를 더 오래 탐 (쉬움 시작 자금·전력 때문에 잦음). 매수금 3.5억은 주원인이 아닙니다. 사람 플레이어는 2020 이전에 연봉을 수입에 맞추면 파산을 피할 가능성이 큽니다.
