# 나이별 훈련 구조 · 2026-11-18

오너 요청: 어린 선수는 피지컬 훈련을 빠르게 배우고, 이후에는 전략적 훈련의 효율이 높아지는 게임 요소를 설계합니다. 아래 배수는 **게임용 설정**이며 실제 사람의 전성기를 단정하거나 선수 기록으로 제시하지 않습니다.

## 이번에 만든 범위

`src/game/training.ts`에 연령 곡선·훈련 세션·피로·개인 진행도 계산을 구현했습니다. **경기 반영은 꺼진 적용 준비 코어**(`AGE_TRAINING_ENABLED = false`)입니다. 현재의 경기·연봉·시즌 카드 능력치는 바뀌지 않습니다. 선수 생년 출처를 등록하고 수동/자동 주간 일정 처리와 연결한 뒤 같은 40개 시드로 재검증하는 것이 다음 구현입니다.

기존 일정은 경기를 시작할 준비 여부만 확인하고 훈련 성장량을 계산하지 않습니다. 생년 정보도 현 데이터에 없습니다. 실제로 확인하지 않은 생년을 채우거나, 카드 수치를 먼저 높이지 않습니다.

## 선수와 나이의 기준

- 프랜차이즈에서는 **선수 개인 식별자 `pkey/person` 하나**를 사용합니다. 카드를 바꾸거나 해가 바뀌어도 같은 사람의 진행도입니다. 연도별 실기록은 시즌 기준 자료로 자동 선택합니다.
- 나이는 커리어의 **현재 날짜**와 확인한 실제 생년월일로 계산합니다. 카드에 적힌 과거 연도로 나이를 되돌리거나 PC의 오늘 날짜를 사용하지 않습니다.
- 생년에는 날짜·출처 URL·확인일이 필요합니다. 생년이 없거나 유효하지 않으면 **생년 정보 없음**, 효율은 중립 1.0입니다. 0세나 추정 생년으로 채우지 않습니다.
- 생일을 기준으로 만 나이를 표시하고 효율은 사이 나이를 보간해 매끄럽게 바뀝니다. 2월 29일생의 평년 생일 경계는 이 게임에서 3월 1일로 계산합니다.

## 훈련 종류와 효율

| 나이 기준점 | 피지컬 숙련 | 전략 이해 | 회복 |
|---|---:|---:|---:|
| 16 | 1.15 | 0.95 | 1.10 |
| 19 | 1.20 | 1.00 | 1.10 |
| 22 | 1.05 | 1.15 | 1.05 |
| 24 | 1.00 | 1.20 | 1.00 |
| 28 | 0.97 | 1.15 | 0.98 |
| 34 이상 | 0.95 | 1.10 | 0.95 |

기준점 사이는 선형 보간합니다. 16세 미만은 16세 기준점을 사용하며 실제 참가 가능 여부는 별도 규칙입니다. 고령이라고 기본 종합이나 성장 상한을 깎지 않습니다. 같은 60분에 얻는 진행도만 달라집니다.

- **피지컬 숙련:** 라인 조작·실행 연습에 해당하는 게임 진행도입니다.
- **전략 이해:** 복기·맵 운영·오브젝트 판단 연습에 해당하는 게임 진행도입니다.
- **회복:** 훈련 피로를 낮춥니다. 하루 한 세션, 과거 날짜나 같은 날짜의 중복 적용을 막습니다.
- 기본 획득량은 10 XP, 진행도가 높으면 추가 획득이 줄고 피로가 높아도 효율이 낮아집니다. 각 진행도는 0–100, 피로도 0–100으로 제한합니다.
- 임시 경기 보정 제안은 분야별 최대 3%입니다. **아직 경기에 연결하지 않았습니다.** 기본 시즌 카드의 실제 수치·가격·기록과 분리된 입력으로만 연결해야 합니다.

## 이어서 적용할 순서

1. 실제 생년 출처를 선수별로 수집·검증합니다. 확인하지 못한 선수는 중립 효율입니다.
2. `Save`에 사람별 진행도를 선택 필드로 저장하고 이전 저장 파일은 0 XP·피로 0으로 시작합니다. 생년 결측을 0세로 만들지는 않습니다.
3. 훈련/스크림/휴식을 피지컬·전략·회복 세션으로 연결합니다. 달력의 날짜가 건너뛸 때 처리한 날짜를 저장하고, 화면을 여는 행위로 훈련을 반복 획득하지 않습니다. 수동 경기와 자동 감독에 같은 경로를 사용합니다.
4. 선수단 화면에 나이·생년 확인 여부·효율·예상 진행도·피로를 보여 주고 자동 감독도 훈련과 휴식을 배정합니다.
5. 임시 효과의 적용 지점을 정해 원본 `CARDS`/`PL`을 수정하지 않고 경기 입력에 합성합니다. 특정 경기나 선수의 승리를 지정하지 않습니다.
6. 켜기 전 타입·빌드·단위 검사, PC 1280/휴대폰 390·콘솔 오류 0, 공식 쉬움 1–40/보통 200–239/어려움 300–339를 한 프로세스씩 재검증합니다.

현재 검증 가능한 생년 사례: [Guinness World Records의 Faker 기록](https://www.guinnessworldrecords.com/world-records/729977-oldest-player-to-win-the-league-of-legends-world-championship)은 생년월일을 1996-05-07로 명시합니다. 이 사실이 연령 효율 곡선의 실증 근거라는 뜻은 아닙니다. 코어는 확인한 생년 자료를 입력받도록 되어 있으며 실제 선수 생년 목록을 임의 생성하지 않았습니다.
