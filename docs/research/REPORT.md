### 1-1. 웹 빌드 구조 (구조만 확인했고 코드는 가져오지 않았습니다)
- `https://html-classic.itch.zone/html/20550973/index.html` 파일 하나가 약 **24MB**입니다. 글꼴(Pretendard)과 이미지 38개가 base64로 들어 있고 `<script>` 블록이 91개입니다.
- 저장은 localStorage와 IndexedDB를 씁니다. 경기 관전은 canvas 2D로 그립니다. 설정에서 매치엔진을 "구/신 페퍼 엔진" 중에 고를 수 있습니다.
- 확인한 기능 문자열(모두 화면에 쓰이는 이름):
  - 대회: LCK컵, 정규 시즌, 플레이오프, 퍼스트 스탠드, MSI, 월즈, KeSPA컵, 국가대표전(아시안게임, ENC), 해외 리그(LPL·LEC 등)
  - 경기: 밴픽(피어리스, "첫 선택권 — 1세트 블루 진영"), 경기 관전(2D 미니맵, 줌인 장면), 하이라이트, 경기 전·후 기자회견
  - 선수단: 1군·2군(CL), 콜업, 육성 강도, 개인 훈련, 챔피언 숙련, 컨디션·사기·멘탈, 면담, 계약 해지
  - 시장: 이적시장(스토브), 재계약, FA, 이적 루머, 스카우터 2명(현재 능력·잠재력을 보는 "눈"), 솔로랭크 발굴, 트라이아웃 신인
  - 경영: 예산(첫 화면 60억), 연봉, 스폰서(메인·서브), 굿즈, 팬미팅, 팬심, 구단주 신뢰도·시즌 목표
  - 기록: 소식(뉴스 피드), 리더보드, 올프로, 신인왕, MVP, 시상식, 명예의 전당, 감독 프로필(트로피 캐비닛, 업적), 기록실
  - 기타: 패치 노트에 따라 바뀌는 메타(챔피언 너프·버프), 은퇴와 신인 등장, 히스토리 모드와 "로스터팩", 선수 능력치 편집
  - 온라인: 타이틀 화면에 "온라인 모드 'LCK: FLIP' 개발 중!"이라고 나옵니다. 빌드 안에도 매칭, 방 만들기, 친선전, 관전 문자열이 있습니다.
- 빌드 안에 개발용 점검 문구가 많이 남아 있습니다(예: "시상식이 아닌데 …가 나온다"). 자체 테스트 코드가 배포본에 같이 들어간 것으로 보입니다.

## 2. 강점과 약점

**강점**
1. 범위가 아주 넓습니다. LCK 1년 일정(컵, 정규, MSI, 월즈, 국가대표)과 운영 요소(이적, 재정, 2군, 언론)를 거의 다 갖췄습니다.
2. 이야기 요소가 강합니다. 뉴스 피드, 기자회견, 면담, 루머, 시상식, 명예의 전당이 장기 플레이 동기가 됩니다.
3. 업데이트가 빠릅니다. 8월 공개 후 3개월 만에 Alpha v8.28이고, 디스코드로 피드백을 받습니다.
4. 설치 없이 웹에서 바로 하고, JSON 백업과 영어판이 있습니다.
5. 사진은 사용자가 넣는 데이터 팩 방식이라 초상과 자산 문제를 배포본에서 피합니다.

**약점** (댓글이 적어서 대부분 구조와 문서에서 추론한 제 판단입니다)
1. 능력치가 실제 경기 기록이 아니라 제작자가 정한 값(OVR)입니다. 근거나 표본 수가 화면에 없고, 사용자가 고칠 수 있습니다.
2. 무겁습니다. 24MB 파일 하나를 받고 첫 실행 때 엔진 점검을 합니다. 모바일은 "넓은 화면 권장"입니다.
3. 경기 결과가 왜 그렇게 나왔는지 데이터로 설명하지 않습니다. 제작자도 로드맵에 매치엔진 개선과 관전 UI 개편을 적어 두었습니다.
4. 저장이 브라우저 하나에만 묶여 있어서 백업을 잊으면 잃습니다.
5. 아직 Alpha이고 점검 문구가 배포본에 남아 있습니다. 공개 평점이나 리뷰가 없어 완성도를 밖에서 검증하기 어렵습니다.
6. 교육용 기능(수업 시나리오, 학생 결과 보고서, 데이터 출처 안내)이 없습니다.

## 4. 법·IP 주의점 (사실 위주, 법률 자문은 아닙니다)

1. **Riot "Legal Jibber Jabber"** (https://www.riotgames.com/en/legal, 2018년 8월 개정)
   - 무료 비상업 팬 프로젝트에만 제한적으로 허락합니다. 크라우드펀딩, 법인이 관여한 프로젝트, 유료 장벽은 금지입니다(예외: 광고 수익, 스트리밍 후원, API 정책을 지키고 유효한 API 키를 쓰는 상업 제품).
   - **3조 "No unauthorized games or apps"**: Riot IP(챔피언 외형, 능력, 맵, 아이콘, 아이템 등)를 게임이나 앱에 쓰지 말라고 합니다. 앱스토어나 구글 플레이 배포는 서면 라이선스나 유효한 API 키가 있어야 합니다.
   - 5조: 서면 라이선스 없이 Riot 로고나 상표를 쓸 수 없고, Riot 상표를 넣은 도메인이나 SNS 계정 이름도 안 됩니다. → **"LOL Manager"라는 이름에는 상표 "LoL"이 들어갑니다.**
   - 6조: 공유할 때 "[프로젝트명] was created under Riot Games' "Legal Jibber Jabber" policy using assets owned by Riot Games. Riot Games does not endorse or sponsor this project." 문구를 눈에 띄게 넣어야 합니다.
2. **Riot 개발자 정책** (https://developer.riotgames.com/policies/general, 2025-05-29 개정)
   - 핵심 정책에 "Do not create or develop games utilizing Riot's IP"가 있습니다. 매니저 게임을 API 키 등록 제품(Production 키 신청 대상)으로 올리면 이 조항에 걸릴 가능성이 높습니다. → Production 키 신청은 **밴픽 분석 사이트**로만 하고, 매니저 게임은 미리 만들어 둔 집계 데이터만 쓰는 별도 비상업 팬 프로젝트로 두는 편이 안전합니다.
   - 공식 랭크를 대신하는 MMR/ELO 계산기와, 식별할 수 없는 플레이어를 드러내는 것(de-anonymize)은 금지입니다. → 솔로랭크 데이터는 챔피언 단위로 묶은 집계로만 쓰고, 프로 선수의 솔로랭크 계정을 찾아 붙이지 않습니다.
3. **선수 실명·초상** — 부정경쟁방지법 제2조 제1호 타목(2022-06-08 시행): 국내에 널리 알려지고 경제적 가치가 있는 사람의 성명·초상 등을 "자신의 영업을 위하여" 무단으로 써서 경제적 이익을 침해하면 부정경쟁행위가 됩니다. 손해배상과 금지청구 대상이고 형사처벌 대상은 아닙니다. 출처: https://daily.hankooki.com/news/articleView.html?idxno=832938 , https://www.nepla.net (법 해설). 비상업이면 위험이 낮아지지만 사진(초상)은 더 민감합니다. LCK Manager 26도 기본 배포본에서는 사진을 빼고 사용자 데이터 팩으로 처리합니다.
4. **팀 로고·LCK 로고**: 각 구단과 LCK의 상표입니다. 쓰지 말고 팀 약칭과 색상 칩으로 대신합니다.
5. **LCK Manager 26 자체**: 빌드에 "무단 복제·수정·재배포 금지"가 명시되어 있습니다. 기능과 UX 아이디어만 참고하고 코드, 문구, 이미지, 로고, 화면 배치를 그대로 옮기지 않습니다(분석용으로 받았던 빌드 사본은 지웠습니다).
6. **데이터 출처 표기**: Oracle's Elixir, Leaguepedia(CC BY-SA 텍스트), Riot API 출처를 데이터 출처 페이지에 적습니다.

## 6. 우리가 더 잘할 점 (차별점)
1. **진짜 데이터**: 선수 능력치, 챔피언 강도, 팀 성향을 모두 실제 경기에서 계산하고 표본 수를 같이 보여 줍니다. 숫자를 지어내지 않습니다.
2. **밴픽 깊이**: 이미 검증한 2026 첫 번째 선택권과 피어리스 밴픽에 랭크 상성·시너지와 프로 데이터를 붙입니다.
3. **팀 스타일 AI**: "젠지처럼 밴하는 AI"를 실제 기록 근거와 함께 보여 줍니다.
4. **설명하는 시뮬**: 결과마다 승부를 가른 요인(라인전 골드 차, 조합 상성, 오브젝트)을 근거와 함께 보여 줍니다. 수업 자료로 쓸 수 있습니다.
5. **수업 모드**: 교수님용 시나리오, 학생 결과 보고서, 같은 시드로 공정 비교.
6. **가볍고 빠르게**: 코드 분할, 모바일 대응, 확실한 자동 저장.

## 7. 벤치마킹할 기능 상위 8개
1. 주 단위 "진행하기" 루프(큰 버튼 하나, 다음 일정 자동 이동)
2. 왼쪽 사이드바와 위쪽 자원 칩(자금, 팬심, 구단주 신뢰도)으로 된 FM식 정보 구조
3. 뉴스 피드(경기 결과, 선수 소식, 읽음/안 읽음 표시)
4. 패치에 따라 바뀌는 메타(챔피언 강약 변화 표)
5. 감독 프로필과 트로피 캐비닛, 업적, 시즌 연표
6. 2026 일정 전체(컵 → 정규 → MSI → 플레이오프 → 월즈)와 대진표
7. 스카우팅의 "추정 범위" 개념(스카우터 실력에 따라 범위가 좁아짐)
8. JSON 세이브 내보내기/불러오기와 게임 안 패치노트 팝업

## 9. 기술 계획
- **스택**: Vite + React 18 + TypeScript(기존과 같음). 상태 관리는 작은 스토어 하나(예: Zustand) 또는 useReducer. 라우팅은 GitHub Pages에 맞춘 해시 라우팅
- **새 저장소**: `cancellawerra-bot/lol-manager`(이름은 확정 필요). GitHub Pages로 배포하고 GitHub Actions로 빌드. 기존 `lol-banpick-lab`은 건드리지 않습니다.
- **코드 재사용**: 밴픽 로직(순서, 첫 번째 선택권, 피어리스, AI)을 `App.tsx`에서 떼어 내 `draft/` 모듈로 옮기고, 원본 사이트와 같은 규칙 테스트(`collector/test_banpick.py` 상당)를 TS로 이식
- **시뮬**: 시드 고정 난수(같은 시드면 같은 결과), 시즌 진행은 Web Worker로 처리해서 화면이 멈추지 않게. 결과 분포 회귀 테스트(예: 10,000판 시뮬 승률이 데이터 범위 안인지)
- **저장**: IndexedDB(idb-keyval), 세이브 스키마 버전과 마이그레이션, JSON 내보내기/불러오기
- **성능**: 화면별 코드 분할, 데이터 JSON은 팀·시즌별로 나눠 지연 로딩, 첫 화면 1MB 이하 목표
- **디자인**: 기존 밴픽 사이트(v6.css) 톤을 잇되 사이드바와 대시보드 레이아웃으로. 데스크톱과 모바일 모두 화면 확인 후 배포

## 10. 데이터 계획
- **빌드 단계 스크립트**(Python, 읽기 전용)가 정적 JSON을 만듭니다. 사이트는 이 JSON만 읽습니다.
  1. `teams_2026.json`: LCK 10팀, 이름 변경 병합, 레거시 2팀 제외
  2. `players_2026.json`: 1군 선수, 포지션, 2024~2026 경기별 지표 → 포지션 내 백분위, 경험적 베이즈로 표본 보정, 판수 같이 기록
  3. `champions.json`: 확정 티어(LCK 2026 `champion-tier.locked`), 프로 픽·밴 비율(pro.ts), 랭크 승률(46,494판, 30판 이상만 "신뢰")
  4. `team_style.json`: 팀별 밴·픽 빈도, 라인 우선순위, 선택권 습관(밴픽 33,020건)
  5. `team_laning.json`: 팀 라인전 GD/CSD/XPD(확정본)
  6. `meta.json`: 데이터 기간, 판수, 생성 시각, 출처
- **규칙**: 30판 미만은 "표본 부족"으로 따로 표시합니다. 지어낸 숫자는 넣지 않고, 시뮬 내부 값(난수, 가중치)은 "게임 규칙"으로 따로 밝힙니다. 솔로랭크는 챔피언 집계만 쓰고 선수 식별 정보는 넣지 않습니다.
- **갱신**: 기존 수집기와 LeagueLab 동기화 결과로 스크립트를 다시 돌리면 끝나도록 만듭니다.
